# Generator Sensitivity in Python SAST Benchmarking

# What this is
Free static application security testing (SAST) tools are widely used to find security vulnerabilities in Python code. Recent work has measured how well they actually perform, and the answer is: not very. Liu et al. (ICSE '26) found that no single tool detected more than 40% of vulnerabilities in real-world Python code, and that aggregating all eight tools they evaluated still reached only 66.7%.

Their evaluation used two benchmarks. The real-world benchmark comprises 108 manually verified CVEs. The synthetic benchmark comprises 240 programs — 120 vulnerable and 120 patched counterparts which was all generated by a single model, DeepSeek-V3, from a single prompt.

This raises a question the original study does not address: are the reported tool scores a property of the tools, or partly a property of the model that wrote the test code? Different models have different coding habits. A pattern-matching analyzer only fires on patterns its rules cover, so a shift in generation style could move a tool's measured score without the tool changing at all.

This project regenerates the synthetic code benchmarks using additional language models, holding everything else constant, and tests whether the published tool rankings hold. 

# Research Questions
RQ1: Do the precision, recall and F1 scores reported for free Python SAST tools replicate when the synthetic benchmark is regenerated by a different model using the same prompt?
RQ2: Does per-CWE coverage shift across generators, and if so, which tools and weakness classes are most affected?
RQ3: Does the complementarity of tools hold across all generators
