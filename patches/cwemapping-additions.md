# CWEMapping deviations

## Why this file exists

`CWEMapping/*.txt` maps each tool's alert descriptions to CWE numbers.
The upstream files were generated by running `parse.py <tool> collect`
over PySASTBench's own DeepSeek-V3 corpus, so they contain entries only
for rules that fired on that corpus. A rule that fires on a different
corpus has no entry, and `evaluate` aborts with
`This description not mapped: <description>`.

Every addition below was required to score a corpus other than
DeepSeek-V3. None changes an existing upstream entry.

## Assignment rule

Applied uniformly:

- A rule that detects one of the six target classes (CWE-22, 77, 79,
  89, 94, 502) gets that CWE number: `description;<cwe>`.
- Any other rule gets a bare line with no number, which registers the
  description as known while excluding its alerts from scoring. This
  matches how upstream handles out-of-scope rules such as
  `assert_used` and `hashlib`.

No description was assigned a CWE it does not directly detect, and no
description was left unmapped in order to suppress an alert.

## Deviations

### CWEMapping/Bandit.txt

No additions. The file was accidentally overwritten by
`parse.py Bandit collect` on 2026-11-22 — `collect` regenerates the
description list without the CWE annotations — and restored from
upstream with `git checkout`. `collect` is not used anywhere in this
study's scoring procedure.

### CWEMapping/Codeql.txt

| Line added | Assigned | First triggered by | Date |
|---|---|---|---|
| `SimpleXMLRPCServer denial of service` | none (out of scope) | GPT-Sol-6.1 | 2026-11-21 |

Denial of service is outside the six target classes, so the alert is
excluded from scoring rather than counted against any class.

### CWEMapping/Dlint.txt

| Line added | Assigned | First triggered by | Date |
|---|---|---|---|
| `DUO135 enable all "forbid_*" defenses when using "defusedxml" parsing` | none (out of scope) | Claude-Opus-5.5 | 2026-11-23 |

Consistent with upstream's treatment of `DUO107 insecure use of XML
modules, prefer "defusedxml"`, which is also unmapped. XXE (CWE-611)
and XML entity expansion (CWE-776) are outside the six target classes.
Upstream's mapping contains DUO107 but not DUO135 because the
DeepSeek-V3 corpus uses the insecure XML modules while Claude-Opus-5.5
uses the hardened library.

compile cleanly under `py_compile`, so it is a false positive of that
rule rather than a syntax defect in the corpus.

## Re-scoring protocol

Adding a mapping line changes how alerts score, so after any addition
all three arms are re-scored against the same mapping files:

```
python parse_baseline.py <tool> evaluate   # DeepSeek-V3
python parse.py          <tool> evaluate   # GPT-Sol-6.1
python parse_claude.py   <tool> evaluate   # Claude-Opus-5.5
```

Figures reported in the paper come from runs made after the final
addition, so no arm is scored against a less complete mapping than
any other.

## Verification

`patches/CWEMapping-snapshot/` holds the exact mapping files used for
all reported results. To confirm a run reproduces:

```
diff -r patches/CWEMapping-snapshot ~/Documents/PySASTBench/CWEMapping
```
